Engineering under the hood

The foundations few have.

Before the modules, what holds it all together — precisely the "invisible" part in a demo, but the most expensive to build and the hardest to copy.

Analytical math engine

Real dilution chemistry (3 strategies), concentration calculation and 20-digit Decimal precision (zero floating-point error). Every calculation records the formula used in the audit trail. Requires a chemist + engineer.

Universal unit conversion

Mass and volume (kg·g·mg·µg·ng / L·mL·µL) + density conversion (mass↔volume), used by any module — lab, inventory, production.

Unified cryptographic trail

SHA-256 chaining + Ed25519 signature across the 12 modules, with the "meaning of the signature" (21 CFR Part 11 §11.50). Alter one character, the chain breaks.

Multi-tenant + security

Physical isolation with one PostgreSQL schema per company, RBAC by department and MFA. One company's data is inaccessible to another.

Native integration — "everything linked" (not middleware)

A single data model where a datum is born in one module and runs the cycle by itself (assay → CoA → training → competency matrix). Not separate systems joined by fragile connectors — it's one organism. It can't be added later; it must be designed from day 1, and it's what makes the system non-substitutable by procurement.

Security & data protection

Enterprise-grade security, built in.

Authentication, sessions and data protected with the practices a security audit (and GDPR) expect — not a "basic login".

Passwords & authentication

Passwords with bcrypt (never plaintext). Constant-time login (compares against a dummy hash) so response timing never reveals which emails exist. Generic error messages.

Brute-force protection

Rate limiting in two layers: per IP (in memory) and per account + IP in the database with progressive lockout — evaluated before bcrypt, so a blocked attempt costs no hashing.

Secure sessions

HttpOnly + Secure + SameSite cookie (XSS/JS-proof, HTTPS-only). It holds only a 256-bit random token; the real session lives on the server — revocable, with a 2h expiry and IP/device logging.

2FA (two-step)

Optional TOTP: the password alone creates a pending session that accesses nothing until the 2nd factor. The TOTP secret is encrypted at rest (AES-256-GCM). Enforcement available for admins.

Multi-tenant isolation + RBAC

Each company in an isolated PostgreSQL schema — one company's data inaccessible to another. Access control by department and level (structural RBAC).

Integrity & files

SHA-256 + Ed25519 trail on every record. Private uploads — files served only via an authenticated, tenant-scoped API, never a public folder. Legacy IDOR flaw removed.

Module-by-module evaluation

The modules and their premium features.

For each module: what it does, what's rare/premium, and why it's hard to replicate.

LIMS

Laboratory — Analysis

From sample intake to the Certificate of Analysis, with method-guided execution.

  • Step-by-step assay wizard
  • Dilution engine with real chemistry (3 strategies)
  • Concentration calculation + 20-digit precision
  • Every calculation audited with the formula used
  • Immutable CoA generated in 1 click
  • Segregation of duties (the analyst doesn't approve)
  • Sample retention (reserve samples) with controlled disposal
  • Regulatory reports and lab analytics
Rare because: correct analytical calculation requires a chemist + engineer together; audited decimal precision is 21 CFR grade — not every premium commercial LIMS has it.
QMS

Quality Control & Lab Inventory

Reagents, solutions, calibration curves, equipment and specifications — with automatic consumption.

  • Method as flowchart with automatic consumption
  • Calibration curves (serial / global / per-point)
  • Mother solution, batches and kits
  • Blocks expired reagent / uncalibrated equipment
  • Culture media prep + sterilization (microbiology)
  • Inventory correction with full traceability
Rare because: poka-yoke that prevents use (not just records it); microbiology is usually a separate LIMS; consumption auto-debited by method.
DMS

Documents

Procedures always on the current version, with approval, distribution and traceability.

  • Collaborative review with inline comments
  • Automatic character-by-character comparison
  • Digital and touch signature (tablet on the floor)
  • Templates with auto-filled placeholders
  • Distribution controlled by permission
  • Approved document triggers training
Rare because: automatic diff + cryptographic signature + training trigger in a QMS is an uncommon combination.
TMS

Training & Competencies

Paths, quizzes and certificates — with a competency matrix that fills itself.

  • Competency matrix filled automatically
  • Quizzes with automatic grading
  • Attendance sheet digitally signed
  • Defines who must be trained
  • Certificates issued in 1 click
  • Linked to procedures and audit
Rare because: the matrix updates from training and documents — the auditor asks, you open the screen. No spreadsheets.
BPM

Workflows & Forms

Design the process once; it runs, chases, notifies and records itself.

  • Visual flow designer
  • Fillable forms per step
  • Approval steps with digital signature
  • Documents and forms attached to steps
  • Panel of running instances
  • Configurable without code
Rare because: BPM + forms + signature native and linked to documents, not an external add-on.
WMS

Logistics & Inventory

From receiving to location, with full traceability and lab integration.

  • Hierarchical nesting pallet→box→unit (up to 6 levels)
  • Returnables (IBC, pallet) with pool + tare per level
  • FEFO + automatic location assignment
  • Inventory computes the lab sample by itself
  • Container cleaning validation, cycle count, waste disposal
  • Shipping with FEFO allocation (Product → Allocation → Summary)
  • Code collector / scanner
Rare because: nesting + returnables + FEFO + cleaning validation is dedicated-WMS grade, not "stock control".
MES

Production

The order computes consumption, reserves the lots and execution records what was actually used.

  • Real consumption + mass balance + yield
  • Losses, scrap, reprocessing and lot discard
  • FEFO reservation + picking + Batch Record (EBR)
  • Equipment NC check before running
  • Forward / backward traceability + recall
  • Formulas / recipes (BOM)
Rare because: lot genealogy with recall capability + EBR + mass balance is pharma/food grade, not "order in a spreadsheet".
SGQ

Nonconformity, CAPA & Change

From NC to corrective action, with automatic escalation and document generators.

  • NC from defect catalog → investigation → escalates to CAPA
  • CAPA with 5W2H / 8D, root causes, verification and team
  • Change Control with FMEA + regulatory impact
  • Multi-level change approval
  • OOS with phased investigation + automatic dossier
  • OOS opened automatically from the lab
Rare because: full pharma-grade quality cycle (ICH Q9), automated — NC→CAPA→CC→OOS linked, with generated documents.
GRC

Risk Management (ISO 31000 / ICH Q9)

Proactive risk register that wires itself into the NC/CAPA cycle.

  • Probability × severity matrix → automatic RPN and level
  • Inherent → residual risk (after mitigation)
  • Lifecycle: assess → mitigate → accept with justification
  • Materialize → auto-generates an NC (proactive becomes reactive)
  • Periodic review with history and due-date alerts
  • Mitigation plans and signed trail (Ed25519)
Rare because: a proactive risk register (ISO 31000) that materializes into an NC in the same system — closes the "predicted risk → risk that happened" loop, pharma/food grade.
AUD

  • Audit dashboard and recurrence
Rare because: full ISO 19011 cycle (plan → meeting → evidence → dossier) inside a QMS is uncommon.
